# City Impact — DX-001–DX-007

Локальний демонстраційний прототип, не незалежна верифікація реального волонтерства. Справжній сервер, облікові записи, модерація доказів і зберігання фотографій потребують окремої інтеграції.

## Інваріанти та інтеграція

Єдине джерело стану лишається `mocks/repository.ts`; нового паралельного store немає. Mutation працює на копії, валідує, зберігає та публікує стан один раз. Виняток до commit не залишає часткових нагород.

- Individual source: `completion:<userId>:<questId>`, impact: `impact:<sourceEventId>`. Повторне підтвердження повертає попередній результат без нової транзакції.
- `actualHours` — необов’язковий фактичний час зі звіту, більше 0 і не більше 24. Запланована тривалість квесту не є підтвердженою метрикою.
- Collective source: `collective:<questId>`. Організатор після першої підтвердженої участі публікує виміряний підсумок усієї команди. Редагування замінює підсумок, не додає його вдруге; XP не нараховується.
- Каталог: hours (individual), kg/count/m² (collective). Порожня метрика означає «не виміряно»; виміряний нуль дозволений для спільного показника. NaN, Infinity, від’ємні, неправильні одиниці та дробові count відхиляються.
- Фільтри дат включають обидві межі за `Europe/Kyiv` і використовують дату підтвердження. Невідомі координати не геокодуються й не вигадуються: записи залишаються у списку. Джерело координат території доступне в деталях.
- Мапа не показує текст приватного звіту, контакти чи ім’я виконавця. На ній спільний результат не приписується кожному учаснику.
- Чек доступний лише власнику в демосесії. PNG створюється з окремого privacy-safe набору рядків; не містить звіту, контакту, внутрішніх ID, verifier або приватного URL. Ім’я приховане за замовчуванням. Колективні kg/дерева не приписуються одному волонтеру.
- Фото лише з локальної демобібліотеки; це ілюстрації, не докази реальних змін. Автентичні before/after потребують backend/media-процесу.

## Міграція

Ключ `dniproxp:platform:v5`, schema version 5. При відсутності валідного v5 мігрує v4; старий ключ не видаляється. Зберігаються профілі, заявки, історія звітів, XP/points ledger, обміни та існуючий прогрес. Старий v3 шлях також збережено.

Підтверджені старі участі імпортуються лише за узгодженими completed/confirmedAt/transaction з canonical completion ID. `provenance: legacy-import`, verifier невідомий, фактичні метрики порожні: імпорт не вигадує години та не створює нової нагороди. Некоректний snapshot копіюється в відповідний ключ `:backup`. LocalStorage не є серверною межею безпеки; користувач може змінити його вручну.

## Перевірка і запуск

```sh
pnpm install --frozen-lockfile
pnpm --filter web test
pnpm --filter web build
pnpm --filter web test:e2e
```

Playwright потребує встановленого Chromium (`pnpm --filter web exec playwright install chromium`) або `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` з наявним executable. У sandbox перевірено з `/usr/local/bin/chromium`. Config сам запускає Vite на 5173 (або використовує вже запущений локальний dev server).

Виконано: frozen-lockfile install, 31 Vitest-тест, 6 Playwright-сценаріїв, TypeScript + production build та targeted ESLint нових модулів — успішно. Повний lint має наведені нижче успадковані помилки.

Vitest перевіряє валідацію, межі часу/одиниць, дедуплікацію, Kyiv dates, міграцію без повторних нагород, відмову неавторизованим/чужим організаторам, reject/resubmit, атомарність, колективне редагування, privacy-safe експорт і measured-zero/unknown.

Playwright перевіряє реальний звіт → підтвердження → чек → PNG, спільний результат, клавіатурний slider, offline tiles, порожні/невалідні дати, чужий чек, порожню історію та відсутність горизонтального overflow на 390 px. UI переглянуто на 1365×900 та 390×844.

Повний ESLint має успадковані помилки (hooks set-state-in-effect та react-refresh mixed exports); вони також відтворені на базовому commit `5c7de80`. Нова impact-логіка перевіряється окремо без послаблення правил. Production build попереджає про великий main chunk; оптимізація всього існуючого frontend не входить у цей EPIC.

## Ручний демосценарій

1. «Демо» → волонтер Олександра; відкрити квест «Разом озеленюємо парк», подати заявку.
2. Перемкнутися на організатора «Зелений Дніпро», схвалити заявку.
3. Волонтер: подати звіт, вказати фактичні 1,5 години. До підтвердження нового чека й нагороди немає.
4. Організатор: перевірити звіт та час, підтвердити. Повторна команда не подвоює результат.
5. У цьому ж квесті заповнити спільний підсумок: 15 кг, опис, необов’язкові ілюстрації; зберегти. Подальша зміна на 20 кг має замінити 15, а не дати 35.
6. `/impact`: обрати результат, перевірити фільтри, slider, джерело координат, примітку про демо. При offline tiles список лишається працездатним.
7. Волонтер: «Чеки допомоги», завантажити PNG без імені, потім opt-in з іменем; перевірити історію й показники в кабінеті. Перезавантажити — нагороди та підсумок не дублюються.
